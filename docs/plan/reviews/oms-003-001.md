# Review: oms-003 / pass 001

## Findings

1. **P1 — blocking — Free orders created through lead conversion and marketplace confirmation still auto-assign crew and persist `Unassigned` tasks.**
   - **Design contract:** `docs/plan/analysis/oms-entitlement-and-ux-blueprint.md`, *Product Rules* and *Ownership and Integration Flow* require Free workflow tasks to be assigned to the Studio Owner and prohibit crew/resource suggestions.
   - **Code:** `apps/web/src/actions/leadActions.ts:320-429` and `apps/web/src/actions/marketplaceActions.ts:475-605` still pass full `studioMembers` to preflight/suggestions, construct `assignedResources`, and create workflow tasks with `Unassigned` when no match exists. These are confirmed-order creation paths, so a Free studio can still receive crew operations and non-owner tasks.
   - **Required fix:** Resolve `STUDIO_ERP` in both creation paths; for Free, omit crew data/suggestions and assign all generated tasks to the durable Studio Owner, matching `createOrderCore`.

2. **P1 — blocking — task assignment can still bypass the new ERP gate.**
   - **Design contract:** `docs/plan/tasks/oms-003.md`, *Objective* and *Verification* require `STUDIO_ERP` for every crew mutation and Free workflow tasks to remain Studio Owner-owned.
   - **Code:** `apps/web/src/actions/orders/orderTaskOperations.ts:36-72` (`createTaskCore`) accepts arbitrary `assignedMemberId` / `assignedMemberName` without an entitlement check and defaults Free tasks to `unassigned` / `Unassigned Crew`. `apps/web/src/actions/orders/orderTaskOperations.ts:396-428` (`updateTaskCore`) accepts the same fields and persists them without `STUDIO_ERP` enforcement. `updateTaskAction` publicly exposes that bypass in `apps/web/src/actions/orderActions.ts:151-168`.
   - **Required fix:** Treat creating/updating a crew assignment as an ERP mutation: reject non-owner assignment attempts without `STUDIO_ERP`; Free created tasks must be assigned to the Studio Owner. Keep non-assignment task metadata/status updates available under their existing authorization rules.

3. **P2 — non-blocking — required backend contract tests were not added.**
   - **Design contract:** `docs/plan/tasks/oms-003.md`, *Verification* requires tests for Free rejection and owner assignment.
   - **Code:** commit `16991f8` changes no `tests/` path.
   - **Required follow-up:** Add focused tests alongside the P1 fixes, including direct server-action bypass cases.

## Conclusion

**blocked** — the direct register-order path is improved, but alternative order creation paths and public task mutation actions still violate the Free/ERP entitlement contract.
